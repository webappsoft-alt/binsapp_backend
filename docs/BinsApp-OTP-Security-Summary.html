What Was Changed in the Backend

1. Twilio Error Handling

Files: src/utils/sendOTP.js, src/modules/auth/service.js, src/utils/apiError.js

  • Added parseTwilioError() with clear messages and hints for common Twilio codes.
  • API errors now include a twilio object: httpStatus, code, message, moreInfo, hint.
  • Logs no longer expose Twilio credentials in raw Axios error objects.

2. Debug Logging

File: src/modules/auth/controller.js

  • Logs on send-otp: request context and failures (route, phone, user-agent, error details).

3. OTP Abuse Protection

Files: src/utils/otpProtection.js, src/middlewares/otpSendGuard.js

  • Middleware on POST /api/auth/send-otp — runs before Twilio is called.

4. Region Rules

Files: src/utils/otpProtection.js, src/config/env.js

  • US (+1): all numbers allowed (with rate limits above).
  • Pakistan (+92): only whitelist allowed; all other +92 numbers blocked (e.g. +92355...).

Pakistan whitelist (test numbers):

  • +923467893622
  • +923117384180
  • +923703839371
  • +923006918515
  • +923186159112

Blocked regions/numbers get: "Phone number region is not supported".

Environment Variables (Set on Server)

# Master switch
OTP_PROTECTION_ENABLED=true

# Rate limits
OTP_PHONE_MAX_PER_DAY=3
OTP_PHONE_COOLDOWN_SEC=90
OTP_IP_MAX_PER_HOUR=8
OTP_IP_DISTINCT_PHONES_MAX=5
OTP_GLOBAL_DAILY_MAX=100          # adjust to your real daily OTP volume

# Regions
OTP_ALLOWED_PREFIXES=+1             # US only (do NOT include +92 here)
OTP_PK_WHITELIST=+923467893622,+923117384180,+923703839371,+923006918515,+923186159112

# IP block duration after abuse
OTP_IP_BLOCK_HOURS=24
Important: If server .env has OTP_ALLOWED_PREFIXES=+1,+92, remove +92 or Pakistan whitelist won't work as intended.

Twilio Console Actions (Manual, No Code)

  • Disable auto-recharge — Billing → Payment settings → Auto-recharge OFF.
  • Keep low manual balance only (e.g. $20–50) — when balance = $0, SMS stops.
  • Enable Verify Fraud Guard on your Verify Service.
  • Restrict Geo permissions to US (and PK only if needed for test numbers).
  • Set usage alerts (Usage Triggers) for early warning — alerts only unless you build a kill-switch webhook.
  • Rotate Auth Token if it was ever exposed in logs.

How Protection Layers Work

Request → Rate limits → Region check (+1 open, +92 whitelist only) → If OK → Twilio send OTP → If cap/limit hit → Error (no Twilio call, no charge)

Max theoretical OTP spend ≈ OTP_GLOBAL_DAILY_MAX × cost per SMS
(e.g. 100 × ~$0.05 ≈ $5/day)
